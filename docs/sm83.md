# SM83 instruction model

The CPU module decodes one instruction from a byte span and a 16-bit CPU
address. The returned `Instruction` keeps the original opcode bytes, resolved
mnemonic and operands, length, category, flag effects, data-memory reads and
writes, control-flow type, and any statically known branch target.

Opcode metadata is held in centralized 256-entry tables for base opcodes and
CB-prefixed opcodes. The decoder uses those entries to select instruction
length, operands, and cycle counts instead of repeating per-opcode logic.
Cycle counts are T-states; conditional instructions retain both taken and
not-taken counts. Flag masks use Z, N, H, and C bits. Memory effects describe
data accesses by the instruction, not the CPU's fetch of its opcode or
immediate bytes.

The `$CB` prefix consumes a second opcode byte and selects the CB table. `STOP`
has length two, and its second byte is preserved even though the CPU ignores
its value. The eleven undocumented base opcodes decode to an `ILLEGAL`
instruction with unknown flag, memory, and control-flow behavior; the decoder
does not invent semantics for them.

This module does not execute instructions, model interrupts or hardware timing,
or traverse ROM control flow. The Phase 3 `tool disassemble` command combines
decoded instructions with physical-bank, CPU-address, and ROM file-offset
information using a linear sweep; it does not classify code versus data. See
[disassembly.md](disassembly.md).

Opcode lengths, T-state timings, and flag effects follow the [gbdev SM83
opcode reference](https://gbdev.io/gb-opcodes/optables/); CPU register and flag
semantics are documented in [Pan Docs](https://gbdev.io/pandocs/CPU_Registers_and_Flags.html).
